# 实验体系

测的是一件事：**编译器插入的冗余，在计算数据通路遭遇瞬时单粒子翻转时，用多少开销换来了多少可靠性。**

## 一、负载：17 个，全部来自上游开源项目

| # | 负载 | 上游来源 | 数据类型 | 特征 |
|---|---|---|---|---|
| 1–4 | gemm, 2mm, atax, bicg | PolyBench/C 4.2.1 | FP64 | 规整线性代数 |
| 5 | jacobi-2d | PolyBench/C | FP64 | Stencil |
| 6–7 | ludcmp, durbin | PolyBench/C solvers | FP64 | 线性方程求解、线性预测 |
| 8 | deriche | PolyBench/C medley | FP64 | 图像递归滤波 |
| 9–10 | floyd-warshall, nussinov | PolyBench/C medley | INT32 | 图算法、动态规划，分支密集 |
| 11 | blackscholes | PARSEC（loop-perforation 移植版） | FP64 | 超越函数密集 |
| 12 | kissfft | KissFFT v1.3.1 | FP64 | 混合基 FFT |
| 13 | sobel | llvm-loop-perforation | uint8 | 图像卷积 |
| 14–15 | crc16, quicksort | COAST tests（BYU/LANL） | INT32 | 位运算、递归排序 |
| 16–17 | obpmark_image_prep/proc | **ESA OBPMark v0.3** | uint16/uint32 | 星载影像校正流水线 |

16–17 是唯一真正来自空天领域的负载：偏置校正 → 坏像元替换 → 辐射擦洗 → 增益校正 → 2×2 合并 → 多帧累加，就是卫星成像仪在轨做的事。

自写内核 0 个。所有计算代码都是 `#include` 上游源文件，包装函数只做参数转接。

## 二、指标：每个的分子分母

| 指标 | 定义 | 注意 |
|---|---|---|
| 指令倍率 | 该策略的退休指令数 ÷ 无保护版本的退休指令数 | Linux `perf_event_open` 实测，非估算 |
| SDC% | 输出错误且未被发现的试验数 ÷ 总试验数 | 浮点负载判据：相对 L2 误差 > 1%；整数负载：任何非零偏差；或出现 NaN/Inf |
| 检出并恢复% | 表决器触发恢复且最终输出可用的试验数 ÷ 总试验数 | 不等于"检测率"，见下 |
| 良性误差% | 未触发恢复、但误差在容限内 | |
| Masked% | 相对误差 ≤ 1e-12 | |
| DUE% | 表决三路均不一致，或进程被信号杀死/挂死 | 双模方案的不一致全部计入此项 |
| MWTF | 1 ÷ (指令倍率 × 失效概率) | **主口径用 SDC+DUE 作失效**；只算 SDC 会把双模方案排到前面 |
| QoR | 相对 L2 误差、PSNR、最大绝对误差 | 对双精度黄金参考逐元素比较 |
| 无故障误报% | 没注入任何故障时，表决器触发恢复的比例 | 衡量 δ 是否过小 |

**"检测率 ≥ 95%" 这个说法有歧义，必须区分两种口径：**

- 检出并恢复率 = 37.6%（表决器主动发现并修正的比例）
- 未发生失效率 = 100 − SDC − DUE = 97.5%

开题报告写的"软错误检测率 ≥ 95%"如果按第一种口径，不达成；按第二种口径，达成。论文里必须写明用哪一种。

## 三、故障点分类：七个互斥类别

分类只看指令自身的种类与结果类型，**不看它的使用者**。早期版本用"流入比较/GEP
则排除"来避免类别重叠，副作用是容错变换给被保护指令挂上内联表决之后，那条指令
就变成不可注入——保护越多、注入点越少、可靠性被系统性虚高。按指令种类分类从根上
消除了这个攻击面。

| 类别 | LLVM IR 层 | RV64GCV 落点 | 有注入点的负载 |
|---|---|---|---|
| `fp64` | double 算术/一元运算 | `fadd.d` `fmul.d` | 10/17 |
| `fp32` | float 与 `<2 x float>` 算术 | `fadd.s` `vfadd.vv` | 仅近似策略有（基线无） |
| `int_arith` | i16/i32/i64 整数算术与逻辑 | `add` `mul` `sll` `and` | 17/17 |
| `cast` | trunc/zext/sext/fptrunc/fptosi/sitofp | `fcvt.*` `sext.w` `slli+srai` | 17/17 |
| `load` | load 指令的结果值 | `lw` `ld` `flw` `fld` 目的寄存器 | 16/17 |
| `addr` | GEP 可变下标（扰动限制 ±3 元素） | `sw` `lw` 的地址寄存器 | 16/17 |
| `cmp_branch` | 驱动 br/select/switch 的 icmp/fcmp | `slt` `feq.d` + `beq/bne` | 17/17 |

对应 LLFI/PINFI (DSN'14) 的 arithmetic/cast/cmp/load 与 SASSIFI (ISPASS'17) 的
IOV/IOA。改造前的四类（fp/int/address/branch）覆盖是 11/6/16/**2** 个负载，
最危险的 branch 类只有 2 个负载有注入点。

**预算按类别等额分配**（每类别 500 次），与 SASSIFI（`NUM_INJECTIONS` per IGID
per BFM）、NVBitFI、LLFI/PINFI（每类别 1000 次）一致，不按动态频率比例。自然
频率在聚合阶段作为第二口径（SASSIFI 的 analysis-time weighting）。

## 四、聚合口径

| 量 | 方式 | 依据 |
|---|---|---|
| 指令倍率等比值 | **几何平均** | SWIFT/SWIFT-R 图题 "GeoMean is across all benchmarks" |
| SDC / DUE 等率值 | **算术平均 + 95% CI** | SWIFT/SWIFT-R 的 "Average"；聚合值的 CI 是本工作增量（核查的 13 篇同类工作均未报告） |
| 负载权重 | 套件内等权 → 套件间等权 | Relyzer (ASPLOS'12) 每 suite 等量取样 |
| 类别权重 | 七类等权（主口径）+ 频率加权（副口径） | SASSIFI |

主口径只覆盖**基线程序本身存在的**故障类别。保护方案引入的新故障点（近似副本
带来的 fp32 运算）单列，不混进主口径，否则各策略的类别集合不一致、失去可比性。

实现在 `experiments/aggregate.py`，smoke 与正式报告共用同一套代码。

## 五、故障模型

| 维度 | 覆盖 |
|---|---|
| 指令类别 | fp / int / address / branch，四类分别注入 |
| 空间 | 单比特 SEU、相邻 2 比特 DBU、相邻 4 比特 QBU |
| 时间 | 单次运行注入 k = 1/2/4/8 个独立故障 |
| 位域 | IEEE-754 符号位、阶码、高位尾数、低位尾数分别统计 |
| 采样 | 按动态执行步数均匀采样，每个负载 1000 次（正式）/ 60 次（smoke） |

每次注入在 `fork` 出的子进程里执行：注错把指针写坏导致崩溃、或死循环（100 ms 看护 + 指令预算兜底），都计为 DUE，不影响后续试验。这让 "one fault per run" 落到进程级，与 LLFI/PINFI 的做法一致。

## 六、怎么跑

```bash
python3 experiments/benchmark_harness.py                      # smoke，10 秒
python3 experiments/benchmark_harness.py --full --rq all       # 全量，6 分钟
python3 experiments/benchmark_harness.py --full --rq rq3 --config my.yaml
python3 experiments/generate_html_report.py                   # 看板
```

参数在 `experiments/config/default.yaml`：策略清单、各实验的参数网格、判据阈值、注入次数。换一组对比不改源码。

八组实验：RQ1 机制横向对比、RQ2 选择性保护预算 × 排序算法、RQ3 δ 敏感性、RQ4 自适应切换轨迹、RQ5 位域敏感性、RQ6 MBU 与连发冲击、RQ7 规模扫描、RQ8 指令类别 + RISC-V 交叉验证。

## 七、当前结果

**浮点口径（11 个有浮点注入点的负载，每负载 1000 次注入）**

| 策略 | 指令倍率 | SDC% | 95% CI | 检出并恢复% | DUE% | MWTF(含 DUE) |
|---|---|---|---|---|---|---|
| 无保护 | 1.00 | 14.01 | ±1.91 | 0 | 0 | 12.2 |
| SWIFT | 5.59 | 5.47 | ±1.15 | 0 | 37.53 | 0.8 |
| EDDI | 7.67 | 3.65 | ±0.59 | 0 | 54.99 | 0.5 |
| 精确三模 | 11.62 | 2.54 | ±0.54 | 62.62 | 0.01 | 162.2 |
| **本文方法** | **6.35** | 2.42 | ±0.57 | 37.61 | 0.07 | **247.5** |

**整数口径（6 个整数负载）**：无保护 SDC 32.32% → 本文方法 26.68%，检出并恢复 11.23%；
各策略 DUE 一致为 31.1%，来自地址与控制流故障。

**指令类别分解（SDC%）**

| 策略 | fp | int | address | branch |
|---|---|---|---|---|
| 无保护 | 14.92 | 33.89 | 1.56 | 17.50 |
| SWIFT | 5.83 | 33.89 | 1.56 | 17.50 |
| 精确三模 | 2.73 | 30.00 | 1.51 | 17.50 |
| 本文方法 | 2.35 | 28.20 | 1.56 | 17.50 |

address 与 branch 两列所有策略完全相同：**这两类故障目前零保护**。

**δ 敏感性（17 负载均值）**

| δ | 无故障误报% | 检出并恢复% | SDC% |
|---|---|---|---|
| 1e-7 | 23.67 | 28.76 | 1.63 |
| 5e-5（默认） | 5.88 | 23.88 | 1.65 |
| 1e-3 | 0.00 | 20.29 | 1.73 |
| 0.5 | 0.00 | 16.90 | 2.67 |

δ=1e-7 时 bicg 无故障误报 100%、gemm 94%。默认 δ 下 deriche 仍 100% 误报，
因为它的固有近似误差 7.8e-5 就比 δ 大。单一全局 δ 适配不了所有负载。

**选择性保护（RQ2，MWTF）**

| 排序算法 | b=0.25 | b=0.50 | b=0.75 | b=1.00 |
|---|---|---|---|---|
| semantic（本文） | 8.2 | 18.1 | 33.5 | 49.8 |
| sdctune | 10.9 | 8.3 | 24.3 | 49.8 |
| shoestring | 9.3 | 23.5 | 37.5 | 49.8 |

预算 1.0 时五种排序保护范围相同，数值必然一致。中间预算上 semantic 没有稳定优势。

**自适应切换（RQ4）**：平静期 HIGH 占比 0%，耀斑期 100%，恢复期 10%。
但平静期 5.47M 指令 vs 耀斑期 6.33M，只差 16%——关键代码段在 LOW 档也带保护。

**RISC-V（rv64gcv，qemu）**：本文方法静态指令 336 条中 45.7 条是 RVV 向量指令，
确认向量化生效；SDC 1.52%。只有功能与静态结构验证，无周期数。

## 八、已知局限

1. **各策略注入的不是同一组故障**。插桩后动态指令数不同，注入点集合随策略变化。
   顶会做法是生成与策略无关的故障列表再跨策略重放（Relyzer 等价类、SASSIFI fault list）。
   因此策略间 1 个百分点以内的 SDC 差异不应解读为真实差异。
2. **MWTF 在高可靠区饱和**。精确三模 9/11、本文方法 8/11 个负载实测 SDC = 0，
   失效概率被 `0.5/(trials+1)` 连续性修正钳住，此时 MWTF ≈ 2000/指令倍率，退化成只比开销。
   要有分辨率需把注入次数提到 10000 量级。
3. **无存储器故障模型**。只注入指令结果寄存器，不注入内存单元、cache、寄存器堆。
   Shoestring 注物理寄存器堆，Relyzer 注架构寄存器与地址生成单元锁存器。
4. **无实时性指标**。空天是实时系统，但没有 deadline miss 与恢复延迟的量化。
5. **单次运行**。置信区间只覆盖二项抽样误差，不含 run-to-run 方差（编译不确定性、PMU 噪声）。
6. **无辐照实验**。11 个对标工作中仅 COAST 与 S-SETA 做过中子束测试。
7. **RISC-V 无周期级数据**。gem5 对 RVV 仍有 VLEN ≤ 512 bit 限制；
   唯一集成进 Chipyard/FireSim 的开源 RVV 1.0 应用级向量单元是 Saturn（UCB 2024）。

Scope 应写成**计算数据通路的瞬时软错误**，不要写成"空天计算容错"——存储器、实时性、
长期累积三个维度都没覆盖。

## 九、七类分类下的结果（2026-11-15，每类别 500 次注入）

### 基线的故障风险分布

| 类别 | native SDC% | native DUE% |
|---|---|---|
| `cmp_branch` | **57.23 ± 1.37** | 0.00 |
| `int_arith` | 36.13 ± 1.38 | 25.11 |
| `fp64` | 28.98 ± 1.86 | 0.00 |
| `load` | 25.10 ± 1.29 | 3.77 |
| `cast` | 14.76 ± 1.02 | **57.31** |
| `addr` | 1.90 ± 0.43 | 0.03 |

**最危险的是比较与分支条件（57% SDC），而改造前它只有 2/17 个负载有注入点、
占全部注入点的 0.25%。** 换句话说：之前的实验基本没测到最危险的故障类别。

### 本文方法逐类别的改善

| 类别 | native SDC% | approx_simd SDC% | 变化 | 检出并恢复% |
|---|---|---|---|---|
| `fp64` | 28.98 | **10.33** | **−64%** | 12.69 |
| `load` | 25.10 | **15.70** | **−37%** | 17.43 |
| `cast` | 14.76 | 12.42 | −16% | 4.23 |
| `int_arith` | 36.13 | 34.47 | −5% | 4.57 |
| `addr` | 1.90 | 1.94 | 0 | 1.61 |
| `cmp_branch` | 57.23 | 57.22 | **0** | 0.49 |
| `fp32`（副本自身） | — | 0.73 | — | 49.70 |

近似副本自身被打中时 SDC 仅 0.73%、检出并恢复 49.70%——三路表决对副本故障
是有效的。

### 聚合（六个基线类别等权）

| 策略 | 指令倍率(geomean) | SDC% | DUE% | 检出并恢复% | MWTF |
|---|---|---|---|---|---|
| native | 1.00 | 27.35 ± 0.53 | 14.37 | 0 | 2.4 |
| SWIFT | 1.94 | 24.22 ± 0.49 | 22.08 | 0 | 1.1 |
| EDDI | 2.55 | 20.72 ± 0.47 | 25.48 | 0 | 0.9 |
| LLTFI-SID | 2.29 | 24.34 ± 0.49 | 14.33 | 14.56 | 1.1 |
| exact_tmr | 7.82 | 21.38 ± 0.45 | 14.39 | 14.16 | 0.4 |
| approx_scalar | 8.74 | 21.67 ± 0.47 | 13.48 | 7.46 | 0.3 |
| **approx_simd** | **6.75** | 22.01 ± 0.47 | 14.39 | 6.84 | 0.4 |

### 三个必须正面承认的结论

1. **开销优势被几何平均修正了**。之前用算术平均得到 approx_simd 6.35× vs
   exact_tmr 11.62×（降 45%）；改成几何平均后是 6.75× vs 7.82×（**降 14%**）。
   算术平均被少数高倍率负载抬高了 exact_tmr 的数字。14% 才是正确的说法。

2. **把六类故障等权计入后，没有任何方案的 MWTF 优于不保护**（native 2.4，
   最好的保护方案 1.1）。原因是占权重 1/3 的 `cmp_branch` 与 `addr` 两类
   完全没有保护，而 `cmp_branch` 的 SDC 高达 57%。这不是实现 bug，是
   IR 层值级冗余的原理边界（nZDC, DAC'16 的论点）。

3. **方法真正有效的范围是 fp64 与 load**（SDC 降 64% / 37%），在整数算术上
   只降 5%，在控制流上为零。论文的适用范围应据此写死，不要写成"通用容错"。
