# 免检查点恢复：幂等区间一族

这是文献里**唯一**绕开"常驻三份"的恢复机制，也是我们目前没有走的那条路。

## 机制

把程序切成**幂等区间**：区间内没有内存 write-after-read 依赖，所以可以被重复执行
任意次而不改变语义。检测到故障就跳回区间入口重跑，不需要显式检查点。
于是"恢复"的代价从"常驻冗余"变成"出错时重跑一段"，而单次执行期望故障数极小。

| 工作 | 出处 | 贡献 |
|---|---|---|
| de Kruijf et al. | **PLDI 2012**（被引 122+） | 幂等区间的静态分析与编译器设计，这一族的奠基 |
| Encore | **MICRO 2011** | 低成本细粒度瞬时故障恢复 |
| iGPU | **ISCA 2012** | 幂等重执行支撑 GPU 的异常与投机，指出"ROB 回放对 GPU 过于复杂" |
| Clover | **LCTES 2015** + ACM TACO 2016 | 幂等处理 + 声波传感器检测 + **tail-DMR**：只复制区间尾部的指令来兜住检测延迟 |
| Bolt | **SC 2016** | 编译器导向的轻量检查点，细粒度恢复 |
| RTailor | **RTSS 2023** | 把"可靠性等级"参数化到混合临界实时系统；明确记 DMR 检测开销可超 100% |
| iDO | NVMW 2019 | 同一技术用在非易失内存的失效原子性 |
| Asymmetric Resilience | **HPCA 2020** | 任务级幂等：靠重跑前序 kernel 代替检查点，无故障开销可忽略 |

## 对我们的意义

- **我们当前的恢复是"前向多数决就地纠正"**：无回滚、无重执行，所以没有恢复延迟，
  但代价是常驻三份。幂等重执行是另一个极端：平时只付检测代价，出错才付重跑代价。
- 已有数据说明为什么我们之前走不通：双模 + 冷路径重执行实测 **周期 −33% 但
  SDC 2.22 → 8.59、DUE 0.02 → 7.64**（只在 store 比）。失败原因是**检测点太稀**，
  被打坏的值在到达检查点前已经变成地址或控制流。
- Clover 的 **tail-DMR** 正是针对这个问题：不是"稀疏检查点"，而是"区间尾部全复制"，
  用区间边界做错误**遏制**（containment）而不是检测。这是我们那次否证没有尝试的变体。
- RTailor 与 Bolt 都强调：**检测方案与恢复方案是正交的**。我们可以保留现有的
  代数校验/三模做检测，只把**恢复**换成幂等重执行。
