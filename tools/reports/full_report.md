# 自适应容错框架 — 统一评测报告

## 1. 保护菜单

- 做什么：每核在各防护策略下的开销与残余失效概率；此处为并行场景，强防护多为 1×，串行下的档位差异见第 4 节
- 指标：
    - native× — 无防护基准，恒为 1
    - e(SDC) — native 的残余每故障失效概率，取实测 fp64 SDC
    - 最便宜强防护 / 其× — 使 e≈0 的最便宜策略及其开销
- 数据源：`results/opt/capstone_menu.csv`

## 2. 策略级覆盖与开销

- 做什么：单比特故障注入下各防护策略的覆盖与开销，按内核取均值
- 指标：
    - SDC% — 静默数据损坏率，越低越好
    - DUE% — 检测到但不可恢复（崩溃/挂起）率
    - 动态指令× — 相对 native 的动态指令膨胀
    - MWTF — 平均无失效工作量，越高越好
- 数据源：`results/opt/fi_outcomes_a4_t200_matrix_solid.csv`

## 3. 少核下包络

- 做什么：粗粒度冗余副本并行放不同核数时的墙钟开销；并行回到 ~1× 要求空闲核≥副本数
- 指标：
    - DMR 并行× — 双模冗余（2 副本）的墙钟开销
    - TMR 并行× — 三模冗余（3 副本）的墙钟开销

## 4. 自适应控制器 payoff

- 做什么：λ(t) 驱动的控制器在真实轨道上的开销，对照全保护与 native；ε=1e-4 faults/s
- 指标：
    - 自适应× — 控制器平均开销
    - 协态× — 由失效预算 B 反解乘子 μ 的最优解
    - 全保护× / native× — 两个静态基线（全程强防护 / 全程不防护）
    - 达标 — 自适应最坏残余失效率是否 ≤ ε
    - 违约% — always-native 超 ε 的时间步占比
    - 失效预算 B — 一次任务允许的期望失效次数上限
- 数据源：`现跑 workload_eval.eval_workload(build_menu())`

## 5. 在线可实现性

- 做什么：λ 不给真值、改从 ECC 泊松事件流在线估计时的开销与违约
- 指标：
    - 裕度κ — 估计值的安全放大因子
    - 开销× — 在线控制器平均开销
    - 违约% — 真实残余超 ε 的时间步占比
- 数据源：`results/opt/capstone_online.csv`
